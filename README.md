# d-clz.github.io

Personal blog, built with [Astro](https://astro.build) and deployed to GitHub Pages.

## Structure

```
.
├── src/content/posts/   # blog posts (markdown)
├── src/data/projects.ts  # projects page content
├── src/components/       # SearchBox.astro — client-side semantic search
├── src/layouts/
├── src/pages/            # routes
├── scripts/
│   ├── build-search-index.mjs   # generates public/search-index.json at build time
│   └── sources.mjs              # pluggable external content sources (see below)
└── public/images/
```

## Developing

```
npm install
npm run dev
```

## Building

```
npm run build
```

This runs two steps:
1. `scripts/build-search-index.mjs` — embeds all posts with a small local model
   ([`Xenova/all-MiniLM-L6-v2`](https://huggingface.co/Xenova/all-MiniLM-L6-v2),
   via [transformers.js](https://github.com/xenova/transformers.js)) and writes
   `public/search-index.json`.
2. `astro build` — builds the static site into `dist/`.

If the embedding model can't be fetched (e.g. no network), the build still
succeeds with an empty search index rather than failing outright — the search
box on the site detects this and shows "search unavailable" instead of breaking.

### Semantic search

Search is fully static: embeddings are computed once at build time, shipped as
a JSON file, and the browser does the query embedding + similarity ranking
client-side (no backend, no API key). See `src/components/SearchBox.astro`.

### Adding external content sources

`scripts/sources.mjs` documents the contract for merging content from other
repos into the search index (e.g. a sibling project's blog/docs). The short
version: an external source should publish plain content
(`{ id, title, url, date, content, tags? }`), not pre-computed embeddings —
embeddings are only comparable when generated by the same model, so this repo
generates all of them itself over the merged corpus.
